# Migrating to simplyprint-ws-client 2.0

2.0 restructures the library around the one axis that matters: **cloud** (talks to
SimplyPrint) vs **device** (talks to the printer). Migration is hard-cut — there are
no re-export shims. `2.0-renames.tsv` in this directory is the machine-readable
old→new map (one row per moved module / renamed class, appended in the same PR as
every move); apply it to your tree, then read the semantic changes below.

## Layer map (target)

```
common/   leaf primitives (events bus, asyncio, worker, utils, model, hardware)
cloud/    the SimplyPrint engine (client, state, protocol, config record, files, api)
device/   everything toward the physical printer        (lands in slice B)
integration/  the authoring kit a vendor subclasses     (lands in slice C)
runtime/  the headless host process                     (lands in slice D)
```

`core/`, `contrib/`, and `shared/` empty out slice by slice and are deleted at the
end. Mid-migration, a directory not yet moved keeps its old path.

## Semantic changes (things a rename map cannot express)

### Slice A

1. **The config record split out of the manager package.** `Config` / `PrinterConfig`
   now live in `simplyprint_ws_client.core.config`; the `core.config` package keeps
   only the storage backends (`ConfigManager*`, `ConfigManagerType`) until they move
   to `runtime/`. A mixed import must split into two imports. The root package's
   explicit exports (`from simplyprint_ws_client import PrinterConfig`) still resolve.
2. **Cloud connection classes are side-prefixed.** `Connection` → `SimplyPrintConnection`,
   `ClientProtocol` → `CloudProtocol`, the `ConnectionEvent` family →
   `SimplyPrintConnection*Event`. (`ConnectionMode` / `ConnectionHint` are unchanged.)
   The wire-event family (now `common.wire.events`) keeps its member names —
   see slice B, item 7.
3. **The identity seam is library-owned.** `assign_unique_id` / `capture_hardware_id`
   (slot UUID assigned once, never re-keyed; MAC capture fallback) and the
   `DeviceReconciler` hardware-identity rule moved from the integration into
   `simplyprint_ws_client.integration.discovery.{identity,reconcile}` (they ride to
   `device/discovery/` in slice B). Configs and discovered devices now implement
   the typed `hardware_identity()`, `network_addresses()`, and
   `primary_network_address()` contract. A brand returns its address values from
   `network_addresses()` directly; identity code no longer reflects over field names.
4. **`build_candidates` takes the cloud accounts as a parameter.**
   `simplyprint_ws_client.integration.discovery.candidates.build_candidates(app, store,
   account_providers={key: provider})` — the library owns the dedupe rule, the app
   supplies its linked-accounts projection. Passing nothing skips cloud candidates.
5. **The per-installation identity salt stays app-side.** `unique_id` is a plain
   slot UUID (the salted-sha1 scheme is legacy); `new_identity_salt` /
   `installation_salt` were deleted — an app that persists the legacy secret mints
   it locally (`secrets.token_hex(32)`).

### Slice B

6. **`contrib.connection` split along the honest seam.** The wire engine is
   side-neutral (the cloud socket rides it too) and lives in
   `simplyprint_ws_client.wire` (transport ABC, `Reconnecting`,
   `RetryPolicy`, `ConnectionState`, errors, the wire events, messages, and all
   fixed Paho MQTT and Websockets WS backends). The device-facing front is
   `simplyprint_ws_client.wire`
   (`Pool`, the lease, keepalive, options, the `mqtt`/`websocket` front doors).
7. **The lease is named `Lease`.** `Connection` → `Lease`, `WsConnection` →
   `WsLease`, `MqttConnection` → `MqttLease`. The wire event base `ConnectionEvent`
   → `WireEvent`; the members (`Connecting`/`Connected`/`Disconnected`/
   `MessageReceived`) keep their names — both sides ride them.
8. **One options path.** `connect()` takes `url`, mandatory `pool=`, and
   `options=` only; the bare `retry=`/`provider=`/`keepalive=`/
   `wire_keepalive=` kwargs are gone — put them on `ConnectionOptions`.
   `ConnectionOptions.with_provider` was removed (use `dataclasses.replace`).
9. **Wire implementation selection is removed.** `mqtt.connect` is always Paho
   and `websocket.connect` is always Websockets. The `impl=` parameters,
   `MqttImpl` / `WsImpl`, and the `wire.aiomqtt` / `wire.aiohttp` transport
   modules were deleted with no aliases; callers using either alternate backend
   must migrate before upgrading.
10. **`MqttLease.subscribe_soon(topic)`** is the sync-side subscribe (records
    routing interest immediately, applies the wire subscribe on the loop) — the
    front door uses it; brand code re-subscribing from sync code should too.
11. **Pool ownership is explicit.** `mqtt.DEFAULT_POOLS`,
    `websocket.DEFAULT_POOLS`, both front-door `shutdown()` functions, and the
    optional-pool fallback were deleted. An app retains protocol-specific
    `PoolRegistry` instances in `ClientContext`; a direct caller creates and
    retains its own registry, obtains a concrete pool with `mqtt.pool_for(...)`
    or `websocket.pool_for(...)`, passes that pool to `connect`, and awaits
    `registry.close()` on its owning loop with its other resources.
    `as_message`, `frame_of`, and the unused `default_topic` were also deleted;
    `Endpoint.refs` is now derived from `len(endpoint.leases)`.

### Slice C (in progress)

12. **The Client hierarchy collapsed 5 → 3.** `DefaultClient` merged into `Client`
    (default message handling is base behavior; opt out by overriding the
    handler). `PhysicalClient` was deleted — nothing subclassed it; call
    `printer.populate_info_from_physical_machine()` yourself and override the
    system restart/shutdown demand hooks if your client *is* the host machine.
13. **The authoring base ships in the library.** `BasePrinterClient` (integration)
    → `simplyprint_ws_client.integration.client.PrinterClient`, hook surface
    unchanged in this step. A brand sits `Client → PrinterClient → {Brand}Printer`.
14. **The driver seam replaces the connection-component wiring.** A concrete
    client must construct and register every `WsDriver` / `MqttDriver` /
    `DevicePoller` in its own `__init__`, after the base constructor, with
    `self.driver = self.attach_driver(driver)`. There is no `device_drivers()`
    hook and no later discovery phase; `client.drivers` is a read-only tuple for
    inspection. The client overrides the async edges
    `on_device_connected(driver)` / `on_device_disconnected(driver, reason)` /
    `on_device_message(message, driver)`; `poll_device()` is the polling cycle,
    `refresh_device_credentials(driver)` the re-auth seam (the driver owns
    single-flight + restart). DELETED from the base:
    `_start_connection`, `_connection_components`, `_connection_event_bus`,
    `_connection_event_bindings`, `_wire_connection_events`,
    `on_connected_to_printer`, `on_disconnected_from_printer`, and the
    `ConnectionEventBinding` alias. `stop_connection` is the public
    extra-teardown hook after drivers stop. Per-brand bridge code (the lease
    plumbing, loop-hop emit, empty event triples) is deleted, not relocated.
15. **JobEdge.** `apply_status(new_status, *, raw=None, downloading=False,
    apply=True)`; the edge hooks are public and typed —
    `on_job_start/on_job_finish/on_job_progress(edge: JobEdge)` with the brand
    payload on `edge.raw` (no more instance-attribute smuggling). The per-call
    `guard_pause=` flag became the `hold_pausing` class attribute.
16. **The demand surface is typed.** `PrinterClient` ships no-op-default
    `on_pause/on_resume/on_cancel/on_gcode/on_terminal/on_skip_objects` +
    opt-in `on_system_restart/on_system_shutdown` (the old PhysicalClient
    behaviors). The reflective `core.autowire` module and `configure` decorator
    are deleted. Core and author-facing routes are registered explicitly at
    fixed priorities; a method name or annotation can no longer create a
    listener implicitly.
17. **One composed file-transfer shape.** `FileTransfer` is final and owns
    admission, cancellation, source download, upload retries, staged START,
    firmware-confirmation timeouts, and teardown. A brand implements only
    `PrintFileDriver` and selects a typed `PreparationKind`; start methods return
    `StartDisposition`, while permanent and retryable failures use the typed
    file-operation errors. Device reports are forwarded explicitly through
    `started()`, `rejected()`, and `progress()`. The subclass hooks, per-brand
    lifecycle machines, and local FileHandler twins are deleted.

**Camera composition hard cut.** `ClientCameraMixin` is deleted. Every
`PrinterClient` now owns a final `CameraController` at `client.camera`; use
`client.camera.uri` and `client.camera.set_uri(uri)`. The four public camera demand
methods remain on `PrinterClient` and delegate to the component, preserving
brand overrides such as device-side stream preparation.

18. **`IntegrationSpec` is an immutable value.** Descriptor subclasses,
    `LazyRef`/`lazy`, and `build()` are deleted. An integration supplies its id,
    client/config factories, metadata, and optional capability fields directly.
    A deliberately deferred import is an ordinary local-import factory, so it
    keeps normal Python identity and remains visible to static analysis.
    Product metadata uses the closed `IntegrationTransport` and
    `IntegrationCapability` string-enum domains while retaining lowercase JSON
    values.
19. **Discovery is explicit.** `IntegrationSpec.discover` is either an async
    `(discovery_service, timeout)` callable or `None`; support is never inferred
    from an overridden hook. Discovery-backed integrations can assign
    `discover_from_service(integration_id, refine=...)`. `Host` constructs one
    `DiscoveryService`, injects it into the frozen `ClientContext`, passes the
    service directly to discoverers and the scoped context to flow factories,
    and owns its restartable lifecycle. The process-global active-service
    accessor and setter were deleted.
    Flow factories now receive that scoped `ClientContext`, rather than a bare
    discovery service, so onboarding can use the same host-owned dependencies as
    the runtime client without a global or a service lookup.
20. **`standard_add_printer_flow(...)`** (integration/flow/recipes.py) owns the
    identify → find → [brand phases] → done skeleton; brands pass the probe,
    the config fold, the catalogue, and extra phases.

### Slice D

21. **The layer tree is complete.** `core/`, `contrib/`, `shared/` are gone:
    `runtime/` holds the host process (app, settings, scheduler, manager,
    config storage, status, cli, debug) and `common/logging` holds the
    stdlib-only logging package (deliberately common, not runtime: the cloud
    client's `printer_logger` import must stay leftward).
22. **`SpecRegistry` + `Host`.** An app's one composition module builds
    `SpecRegistry.of(*integrations)`; every optional surface has a typed registry
    projection (`mdns_specs`/`subnet_specs`/`network_services`/
    cameras/flows/`discoverers`). `Host(registry, settings,
    service_sink=...)` owns startup/shutdown ORDER (discovery -> services ->
    fleet; reversed on stop), exposes its injected discovery service, and owns
    THE persist seam: `host.add_printer(key, config)` = slot id once ->
    hardware de-dup (typed `DuplicatePrinter`) -> the deliberately-dumb
    `app.add`. Programmatic onboarding: `host.flow(key, flow_id)` +
    `run_flow`, `host.discover(key, timeout)`.
    A spec's optional `account_provider_factory(config_manager_type)` is the one
    stateful account-capability factory. `Host` invokes it once, owns the result
    in `host.account_providers`, and injects that same instance into clients and
    flows through `ClientContext.account_provider`. Applications that construct
    `ClientApp` directly must pass their already-owned `account_providers`
    mapping explicitly.

### Slice E

23. **The acceptance proof ships:** `example/headless_vendor.py` is a complete
    vendor integration in one module — config, polling printer client,
    immutable integration value, composed flow — run headless from the library alone
    (`python -m example.headless_vendor`): discovery, programmatic onboarding
    via `run_flow`, the `host.add_printer` seam, the fleet. It is also the
    sibling integrations' reference for the 2.0 host API.

### Post-review revision

24. **Four layers, semantic homes.** Review feedback reshaped the tree:
    `cloud/` + `runtime/` merged into **`core/`** (the protocol engine AND the
    host process; the layer-DAG tooth moved from "nothing imports runtime" to
    "the authoring kit never imports core's host half: app/settings/scheduler/
    manager/host/registry"). `debug/` and `cli/` decoupled and joined
    `common/`. **The whole connection subsystem is `common.wire`** — pool,
    lease, keepalive, options, and the `mqtt`/`websocket` front doors moved in
    with the transport engine (`device.connection` is gone; it was the same
    subject split by consumer). The final tree:
    `common → core → device → integration`, with `device/` = transfer, camera,
    discovery, accounts.
25. **Second review pass.** `events/` and `wire/` are top-level packages (used
    across every layer; `wire` is the whole connection subsystem). `device/`
    merged into `integration/` (same subject: what an integration is made of —
    the kit now holds transfer/camera/discovery/accounts beside the client,
    drivers, spec and flows). The driver family lives in ONE module,
    `integration/drivers.py`, and "Link" is gone: `DeviceLink → LeaseDriver`
    (generic over its lease, so `MqttDriver(...).lease.subscribe_soon`
    resolves), `WsDeviceLink → WsDriver`, `MqttDeviceLink → MqttDriver`;
    the brand attribute convention is `self.driver`. Tree:
    `common → core → integration` with `events`/`wire` as shared subsystems.

### Lifecycle decoupling (post-2.0)

26. **Device work is no longer gated on allocation.** The scheduler used to run
    `init()` only when allocating an active client and `tick()` only once the
    client was fully added to SimplyPrint — but the device drivers started in
    `init`/`tick` are what *detect* device liveness, so any client that lowered
    `active` (at construction like Bambu, or honestly on a device drop) starved
    its own drivers and could never recover. Now: `init()` runs exactly once
    when the client enters scheduling (the new `Client.initialized` flag,
    never reset); `tick(delta)` runs at the tick rate for EVERY scheduled
    client, allocated or not (guard SP-side sends on `is_added()` — the base
    `PrinterClient.tick` already gates its ping); allocation/`ensure_added`/
    `ensure_removed`/`halt` remain keyed on `active` but only move the
    SimplyPrint side. `halt()` therefore no longer means "device work stops":
    `PrinterClient` keeps its drivers running from `init` to `teardown`, and
    `DeviceDriver.suspend()` is **removed** (nothing may park a driver short of
    `stop()`).
26b. **Wire logging is per-printer and semantically named.** The module-logger
    fallbacks renamed `conn.*` → `wire.*` (`wire.mqtt.paho`,
    `wire.ws.websockets`, `wire.pool`, `wire.lease`,
    `wire.reconnect`, `wire.keepalive`), and `ConnectionOptions` (plus
    `MqttConnectParams`/the new `WsConnectParams`) gained a `logger` that the
    pool hands to the transport the first lease builds. `LeaseDriver` defaults
    it to `client.logger.getChild(driver.name)`, so a printer's wire lifecycle
    lands in its own log files (`<uid>/mqtt.log`, ...). Drivers carry
    kind-default names now: `MqttDriver`→`mqtt`, `WsDriver`→`ws`,
    `DevicePoller`→`poll` (override with `name=` as before).
26c. **`custom_webcam_url` is a base `PrinterConfig` field.** Every printer
    supports a user webcam override: the base `PrinterClient.update_camera_uri`
    resolves it ahead of the brand's `resolve_camera_uri`. Presentation fields
    are config-bound snapshots now: `webcam_url_field(config)` reads the current
    value and writes through `PrinterConfig.set_webcam_url`. The removed global
    field objects and string config-attribute mapping have no compatibility
    layer. `default_printer_presentation(image_url, config)` and
    `model_aware_presentation(metadata, catalogue, config, device_type)` require
    the concrete config so every returned editable field is immediately usable.
27. **`active` is allocation policy; typed device sessions own liveness.** A
    device edge never toggles allocation. Each driver retains one immutable
    `DeviceSession` (local generation, reachability, source generation, and
    observation time), so duplicate/stale edges are idempotent. The base client
    aggregates its constructor-attached drivers: idle loss projects
    `PrinterStatus.OFFLINE`
    immediately, while printing or file preparation keeps its current status
    for the bounded `device_loss_grace`. Reconnect does not fabricate
    `OPERATIONAL`; the next device report owns restoration. Camera clearing is
    part of the eventual projection and brands with an independently reachable
    camera opt out through `clear_camera_on_unreachable`. The printer remains
    allocated throughout, preserving setup codes, logs, and connection context.
28. **The application registry is composition-owned, never cached.** The app's
    `build_registry()` returns a fresh `SpecRegistry`; startup calls it once and
    passes that exact instance through `ClientSettings` construction into the
    `Host` owned by `AppContext`; task registration, flows, discovery, and web
    routes all resolve it through that Host.
    Tests build their own registries, so registering a test integration cannot
    leak into another app or test. The old `default_registry()` and
    `PrinterPresentationRegistry` are removed. Presentation and serialization
    now take the already-resolved `IntegrationSpec` explicitly:
    `get_printer_presentation(spec, config)`,
    `PrinterSerializer(spec, config, main_url=...)`, and
    `apply_editable(spec, config, patch)`. The serializer's panel-link base is
    injected from that host's immutable endpoint settings; it no longer reads
    process-global backend state.
29. **Reusable flow steps are composed, not subclassed.** `FieldsStep` and
    `ChoiceStep` are final building blocks. A model-backed form that needs
    state-specific renderer metadata or fields passes `schema_transform=`; a
    choice screen that needs state-specific below-action content passes
    `footer=`. The private `_schema`, `_resolve_fields`, and `_prompt` extension
    methods are removed, and post-processing `run()` merely to rewrite a prompt
    is no longer supported.
30. **Runtime dependencies are app-owned values, never process globals.**
    `SimplyPrintURL` and its mutable collections are removed. `ClientSettings`
    resolves one immutable `SimplyPrintEndpoints` snapshot, `ClientApp` owns one
    `SimplyPrintApi`, and websocket construction receives that app's websocket
    base explicitly. `Client`/`PrinterClient` require and retain a
    `ClientContext`; the connector updater and throttled host-telemetry reader
    live in that context instead of class/module state. Consequently two apps
    in one interpreter can use different backends, API clients, transport pools,
    telemetry caches, and web event hubs without affecting one another. The
    host application's `AppContext` stores the Host once and derives its fleet,
    settings, and discovery service from it; its SSE hub is an owned instance,
    not a module singleton.
31. **Moonraker compatibility is composition, not a brand hierarchy.** The
    generic Moonraker and Snapmaker integrations are now independent final
    `PrinterClient` classes. Each owns a typed `MoonrakerRuntime` constructed
    with its concrete state parser, sender, and HTTP port. The runtime owns
    JSON-RPC state, Klippy edges, HTTP upload/start behavior, and common state
    projection. Snapmaker's file driver receives that runtime explicitly and
    adds only its native tool-map/start transaction; the removed printer,
    device, and file-driver inheritance has no aliases or fallback modules.
    Snapmaker's persisted config is flat, while the two Pydantic wire states
    share only the neutral `KlipperDeviceModel` protocol schema. Snapmaker's
    camera-monitor commands remain `MoonrakerCommand` subtypes because those
    values are literal Moonraker JSON-RPC frames, not reusable brand policy.
32. **One-shot MQTT diagnostics use the wire front door.** The Bambu LAN and
    Elegoo CC2 probes no longer construct raw Paho clients, install callbacks,
    start network threads, or duplicate CONNACK classification and teardown.
    `wire.mqtt_probe.probe_mqtt(...)` leases the caller's owner-scoped
    `PoolRegistry`, returns the closed `MqttProbeOutcome` domain, supports
    required and optional report waits, and publishes typed initial messages
    before a Bambu report check. Brand modules retain only URL parsing, serial
    extraction, and user-facing result text. Probe entry points now require
    `pools=ClientContext.mqtt_pools`; flow and diagnostic factories bind that
    dependency from their scoped `ClientContext`. The synchronous private probe
    helpers are deleted with no aliases.
33. **A stopped `ClientApp` is never restarted in place.** It owns one event
    loop, scheduler, offload executor, and set of terminal transport registries;
    its runner closes those resources when the app loop exits. The host
    supervisor therefore treats an unexpected loop exit as a process-level
    failure and requests a fresh process through `RestartCoordinator` instead
    of calling `run_detached()` on the spent owner. Failure recovery does not
    mark an OTA relaunch as intentional, so a crash-looping trial slot can still
    reach the launcher's rollback threshold.
